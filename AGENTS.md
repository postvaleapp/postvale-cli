# AGENTS.md

Rules for anything (or anyone) writing code in this repo. Re-read
before commits in long sessions.

## This is a public repo

Anyone can read every line. Treat it accordingly.

- No hardcoded credentials, tokens, customer domains, or test data
  that resembles a real customer
- No internal-only Postvale context (private webapp implementation
  details, internal URLs, infra names, deploy hosts)
- No "Generated by..." / "AI-assisted" markers in commits, code,
  or docs. Commits are signed by the human who reviewed them.
- Don't reference the relationship to the private webapp repo
  except where strictly necessary (e.g. the API URL it talks to)

## Code style

- `gofmt -s` clean. CI fails otherwise.
- `go vet` clean.
- Tab indent (Go default).
- Prefer stdlib over deps. Small focused deps are fine.
- One package per concern. Keep `internal/` flat.
- No `panic()` in command code. Return errors; let cobra handle them.
- Output renderers never call `os.Exit`. That's the command's job.

## Comments

Short. One line preferred, two max. Explain WHY, never WHAT.

- The code shows what. Don't restate it.
- Skip the comment entirely if the code is self-explanatory.
- No "Let me..." or "This function..." preambles.
- No listing alternatives considered. That goes in a design doc.
- No marketing prose ("designed to...", "carefully crafted...").
- Package-level docstrings: one sentence.

Bad:
```go
// GlobalFlags holds the values for the global flags. We use a
// package-scoped struct so individual commands can read them
// without having to re-define persistent flags everywhere.
type GlobalFlags struct {
```

Good:
```go
// Persistent flag values, populated by cobra before RunE fires.
type GlobalFlags struct {
```

## No em-dashes

Replace with ` - `, `. `, `; `, `: `, or parentheses. Applies to
comments, doc strings, prose, commit messages, every
human-readable string in the repo.

## Security review every commit

Before pushing, read the diff line by line. Look for:

- Hardcoded secrets, tokens, customer data, internal URLs
- Unbounded reads (`io.ReadAll` on untrusted bodies - use
  `io.LimitReader`)
- Unvalidated user input reaching HTTP / filesystem / exec paths
- New dependencies that haven't been vetted (license, last
  maintenance, transitive deps)
- Debug `fmt.Println`, `log.Printf`, or commented-out code
- TODO / FIXME leaking internal context
- Token leakage via stderr, env, or process args
- TLS skip-verify, weak crypto, or insecure defaults

CLI-specific things to double-check:

- File path arguments must not allow reads outside what the user
  explicitly asked for (no glob expansion on untrusted input,
  no symlink-following without intent)
- `--token` exposed on a shell command line is visible in
  `ps aux`. Docs must point users at env vars or stored creds.
- API base URL is user-supplied via `--api`. Always re-parse
  with `url.Parse` and check scheme/host before use.
- Response parsing must tolerate malformed / missing fields
  without crashing.

## Dependencies

Run `go mod tidy` before every commit. New dep checklist:

- License compatible with MIT (MIT, BSD-2/3, Apache-2.0, ISC, MPL-2.0)
- Active maintenance (commits in last 12 months)
- Reasonable transitive footprint
- No known CVEs (`govulncheck ./...` before push)

## Commits

Conventional Commits. Lower case. Imperative mood.

```
feat(commands): add postvale watch
fix(api): handle 429 rate-limit response
chore: bump cobra to v1.10.2
docs: clarify CI integration example
refactor(output): extract pill rendering
```

First line under 72 chars. Empty line + body if more context
needed. Sign as the human who reviewed the change.

## Tests

- New exported function: add a test
- Parsers / formatters: table-driven
- Integration tests against a real Postvale instance go in
  `tests/e2e/` and are gated by an env var (`POSTVALE_E2E=1`)
- `go test -race ./...` clean before push

## Releases

- SemVer. `v0.x.y` while pre-1.0, breaking changes allowed in
  minor bumps.
- Tagging `vX.Y.Z` triggers GoReleaser via
  `.github/workflows/release.yml`.
- Update `CHANGELOG.md` in the same commit as the tag.

## When in doubt

Prefer the small change that's easy to review over the clever
one that needs a paragraph of justification.
